# 원격·다중 사용자 확장 요구

현재 제품은 단일 사용자의 loopback 서버다. 원격 공개는 이번 구현 범위에 포함하지 않는다. 아래 요구를 충족하는 별도 서비스로 분리해야 하며 현재 서버 주소만 외부에 개방하지 않는다.

## 선택한 설계 기준

제어 계층은 OIDC 로그인과 조직별 권한을 가진 API 서비스, 메타데이터는 PostgreSQL, 제출·근거는 테넌트 키가 붙은 비공개 객체 저장소에 둔다. 실행 계층은 시도별 단명 Linux VM 또는 동등한 강도의 격리 런타임으로 분리한다. 공유 프로세스·공유 호스트 디렉터리로 고객 코드를 실행하지 않는다. 초기 구현 계획은 단명 VM을 기준으로 한다.

## 인증·격리

모든 객체에 tenantId/userId/attemptId를 포함한다. API와 DB 정책 둘 다 소유권을 검사한다. 웹 로그인 쿠키는 Secure/HttpOnly/SameSite로 발급하고 CSRF·Origin 검사를 유지한다. 브라우저 미리보기는 제어 계층과 별도 사이트에 위치시키며 공유 쿠키를 전달하지 않는다. 단기 프리뷰 토큰은 특정 시도·포트·사용자에 묶는다.

## 실행·비밀

런타임은 시작 시 고정된 과제 버전과 허용된 공개 자료만 받는다. 개인 Codex 로그인 파일을 서버로 복사하지 않는다. 원격 모델 호출은 조직이 승인한 서비스 인증 방식을 사용하며 비밀은 런타임 내부 짧은 수명의 프록시 토큰으로 대체한다. 외부 네트워크는 기본 거부하고 과제에 필요한 목적지만 허용한다. 담당자·평가자 런타임에는 사용자 코드 실행 권한이 없다.

## 일관성·비용

사용자별 활성 시도 제한, 조직별 추론·VM 동시 실행 한도, 요청별 멱등성, 실행 lease와 heartbeat, 원자적 제출 manifest를 유지한다. VM 중단과 제출 복사 경합은 lease generation으로 차단한다. 월별 비용 한도·경고·즉시 중단 스위치를 제공한다. 가격·호스팅 공급자는 배포 착수 시 별도로 검증한다.

## 보존·운영

기본 보존 기간은 정책 설정값으로 두고 제출·평가·감사 로그의 삭제 의존성을 정의한다. 조직 계약에 따라 저장 지역과 보존 기간을 확정한다. 삭제 작업은 참조 검사 후 객체·VM·볼륨까지 재시도 가능한 job으로 정리한다. 로그에 원본 비밀·개인 문서를 무제한 남기지 않는다. 운영자는 승인된 진단 메타데이터만 기본 조회한다.

출시 전 격리 탈출, 타 테넌트 ID 교체, 프리뷰에서 제어 API 접근, lease 재사용, 중복 제출, 비밀 유출, 장애 복구, 비용 상한과 삭제 완결성을 검증한다.
