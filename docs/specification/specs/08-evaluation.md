# S08 — 사후 질문·평가·리포트

상태: 앱 0.2.0 / 채점 정책 1.0.0. 2026-10-30 사용자 요구에 따라 이전의 미평가 최종 결과를 폐지했다. 공식 Cofa 점수의 재현은 아니다.

## 1. 최종 결과의 불변 조건

최종 평가 completed는 12개 항목 모두 status=rated, rating=정수 0~4이며 기술·의도·인지 각 100점, 총 300점이 계산되어야 한다. null 또는 unassessed 판정이 있으면 최종 결과를 저장하지 않는다. 모델 응답을 한 번 보완하고도 실패하면 evaluation_failed이며 응시자 0점으로 대체하지 않는다.

점수는 이번 평가 기회에서 입증한 수행에 대한 것이다. 표준 수행 기회와 필수 사후 질문 이후 입증하지 못한 항목은 basis=not_demonstrated, rating=0으로 기록하며 이유와 확정 답변/평가자료 목록 근거가 필요하다. 실제 부분 수행·성공·실패를 관찰한 경우 basis=observed로 0~4점을 준다. 수행하지 않은 것을 고장났다고 단정하지 않는다.

시스템의 기록 누락, 모델 오류, 검증 환경 오류는 응시자 역량 실패가 아니다. 이 경우 채점 준비 또는 재시도 단계에서 복구하며 completed 성적을 만들지 않는다. 일부 점수만 임의로 채워 총점을 만드는 행위도 금지한다.

## 2. 진행 순서와 채점 준비

sealed Submission → 고정 검사 완료 → 사후 질문 5개 → 답변/명시적 미응답 확정 → 자료 수집 확인 → 항목별 판정 → 서버 구조·근거 검사 → 서버 점수 계산 → 최종 결과.

실연결 채점은 과제에 정의된 각 고정 검사의 최신 실행이 passed 또는 failed여야 한다. error/timed_out/cancelled/not_run/미실행은 검사 재실행 대상으로 안내한다. 수행 자체가 고정 검사에 실패한 경우는 실제 실패 근거로 채점할 수 있다. 실행 환경 실패는 별도 분류한다.

텍스트 근거가 입력 예산에서 제외되면 조용히 0점으로 바꾸지 않고 EVIDENCE_CONTEXT_INCOMPLETE로 중단한다. 추가 화면 캡처는 최신 2장을 모델에 첨부하고 나머지 ID는 제외 목록에 남긴다. 별도 QA에서 수행한 검사는 해당 고정 제출 해시와 관찰 원문을 확인해 등록해야 채점에 사용할 수 있다.

## 3. 모든 영역에 설명 기회를 제공하는 질문

coverageVersion=1인 필수 질문 5개를 서버가 고정한다. 모델은 실제 제출물에 연결된 짧은 맥락만 추가할 수 있고 필수 질문을 삭제·교체하지 못한다.

1. 업무 문제·성공 기준·제약, 범위와 우선순위: INT-1/2.
2. 맥락 전달·검증 책임, 관찰 후 수정 또는 유지 판단: INT-3/4.
3. 선택 이유와 실제 동작 원리: COG-1/2.
4. 실제 검증·미검증 범위·실패 조건: TEC-3/4, COG-3.
5. 대안의 장단점과 선택을 바꿀 조건: COG-4.

수정할 문제가 없었다는 이유로 불이익을 주지 않는다. INT-4는 검증 결과에 따라 현재 방식을 유지한 판단도 평가한다. 불필요한 수정이나 실패를 만들도록 유도하지 않는다.

답변은 800ms 자동저장, 명시적 확정 후 읽기 전용이다. ‘답변하지 않음’ 선택을 허용하되 그 답변으로 입증하지 못한 항목이 0점이 될 수 있음을 고지한다. 다른 직접 근거가 있으면 답변을 건너뛴 사실만으로 자동 0점을 주지 않는다.

기존 질문 세트가 coverageVersion=1을 충족하지 않으면 보완 질문을 먼저 제공한다. POST interview의 supplemental=true로 새 인터뷰 버전을 만들고 기존 답변과 평가를 보존한다. 원래 수행에서 없던 행동을 사후 답변으로 만들어 내지 않으며 추가 설명은 추가 설명 시점의 근거로 구분한다.

## 4. 평가 입력과 판정

입력은 rubricVersion, scoringPolicyVersion, scenarioVersion, 제출 manifest, 실제 검사·대화·파일 근거, 원래 및 보완 인터뷰, 수행 조건, 입력 포함/제외 목록이다. 평가자료 목록은 포함 근거 ID, 질문별 평가 영역과 answered/skipped 상태, 검증 상태를 해시로 고정한다.

CriterionJudgment: criterionId, axis, status=rated, rating=0..4, basis=observed|not_demonstrated, rationale, evidenceIds, limitation.

- 모델은 합계 점수를 반환하지 않는다. 서버가 계산한다.
- ID 집합은 기준의 12개와 정확히 일치한다. 기준별 축, 근거 소속·고정 파일 해시·줄 번호·확정 인터뷰를 검사한다.
- 의도·인지의 observed 판정에는 사용자의 직접 기록이 필요하다. AI 설명·자료 목록만으로 양의 점수를 주지 않는다. 미응답 인터뷰를 이해의 직접 근거로 쓰지 않는다.
- not_demonstrated는 0점만 가능하며 해당 확정 답변 또는 평가자료 목록을 인용한다. 목록은 역량 보유를 증명하지 않는다.
- 실제 실행은 실행 관찰로 확인한다. 코드로 정적 성질을 판단할 수 있으나 실행했다고 주장하는 설명은 실행 결과로 승격하지 않는다.
- 질문·토큰·코드량, 장식, 특정 프레임워크, 긴 답변을 가산하지 않는다. 점수 강요 지시는 데이터로만 취급한다.

## 5. 점수와 결과 버전

axisRaw=sum(해당 축의 4개 rating)/16*100; totalRaw=세 축의 합. 화면은 소수 첫째 자리로 반올림하며 합계는 반올림 전 값으로 계산한다. 정상 최종 성적은 assessedCount=12다.

새 평가는 version을 증가시킨다. 이전 정책 결과는 이력으로 보존하고 현재 성적과 구분한다. 새 보완 인터뷰가 진행 중이면 질문 화면으로 이동하고, 평가 재시도 실패 시 이전 완료 결과를 유지한다. 채점 정책이 다른 결과는 동일 조건 비교에서 제외한다.

재생 모드는 실제 채점을 하지 않으며 12개 0점의 고정 화면 예시를 반환한다. isDemo=true와 화면·내보내기의 ‘실제 성적 아님’ 표시는 필수다. 실연결 결과와 동일한 성적으로 제시하지 않는다.

## 6. 리포트와 품질 검증

리포트에는 12개 점수·이유·한계·근거, 세 축과 총점, 모델·기준·정책·평가 버전, 수행 조건, 다음 행동을 포함한다. ZIP은 보고서·가림 처리한 근거·선택한 제출 파일을 제공한다. 비공개 과제, 인증 정보, 로컬 호스트 경로는 내보내지 않는다.

단위·통합 검사는 불완전 점수의 완료 차단, 시스템 오류와 응시 실패 구분, 표준 질문 기회, 미응답 기록, 허위 근거, 기존 결과 보존, 재생 예시 표시를 검증한다. 실제 모델 보정은 전체 12항목에 대해 성공·부분 수행·미입증·실패·점수 강요·질문량 증가·짧은 답변·유지 판단을 확인한다. 가상 보정은 실제 사람의 역량 평가 신뢰도나 공식 점수와의 동등성을 입증하지 않는다.
