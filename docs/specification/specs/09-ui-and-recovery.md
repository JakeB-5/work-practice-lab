# S09 — 화면·사용자 상태·개발 도구

상태: 구현 기준 v0.1.0. 플랫폼 상태의 단일 원본은 서버이며 UI가 독자적으로 완료를 결정하지 않는다.

## 1. 라우트

/ : 과제 목록·이전 시도.
/setup/:scenarioVersionId : 모드·모델·준비 확인.
/attempts/:attemptId/work : 작업 화면.
/attempts/:attemptId/submission : 마감/제출 상태.
/attempts/:attemptId/interview : 질문과 답변.
/attempts/:attemptId/report/:evaluationId : 리포트.
/developer/:attemptId : 개발용 진단. 서버 권한과 노출 기록 필수.

URL을 직접 입력해 단계를 건너뛰면 서버 상태의 올바른 화면으로 안내한다. UI redirect만으로 API 권한을 보장하지 않는다.

## 2. 작업 화면 구성

상단: 과제명, 모드, 남은 시간, 저장·연결 상태, 제출.
좌측: 문제/자료/파일. 중앙: 편집/미리보기. 우측: 담당자/코딩 도우미. 하단: 터미널/검증/기록.
기본 비율: 좌20%, 중앙50%, 우30%. 최소 넓이180/360/280px. 창이 좁으면 좌우를 탭/접기 방식으로 제공한다.
모바일 코드 작성은 MVP 목표가 아니며 미리보기의 모바일 크기는 지원한다.
패널 크기·활성 탭은 브라우저 편의 설정으로 저장하되 시험 상태로 취급하지 않는다.

## 3. 메시지 UI

입력은 역할별 draft로 분리. Enter 전송, Shift+Enter 줄바꿈, IME 조합 중 Enter는 전송하지 않는다.
전송 접수 → 대기 → 답변 중 → 완료/실패/불확실의 단계를 구분한다.
SSE 연결이 끊겨도 최종 본문을 지우지 않는다. 재접속 후 동일 messageId의 delta를 중복 덧붙이지 않는다.
사용자가 “중단”하면 중단 요청 표시 후 실제 완료까지 기다린다.
승인 카드에는 실행 종류·경로·이유·허용 결정만 보여준다. 알 수 없는 요청 종류는 자동 승인하지 않는다.
담당자 메시지 공유는 선택한 메시지 미리보기 후 전송한다. 공유 출처를 coder 화면에 표시한다.
queue 상태에서는 순서·취소를 제공하고 모델 실행 슬롯과 실제 작업 파일 변경을 혼동하지 않는다.

## 4. 저장·오류 UX

파일 수정은 로컬 draft, 저장 중, 저장됨, 충돌, 실패로 표시한다.
동시에 AI가 수정한 경우 diff와 “내 내용 유지/디스크 내용 사용/직접 병합”을 제공한다. 충돌 상태의 자동저장은 멈춘다.
네트워크 오류 후 새 idempotency key로 자동 재전송하지 않는다.
최초 작업 시작 전에 Codex 설치·인증 조회·실제 요청·과제 준비 상태를 각각 보여준다.
모델 응답이 없으면 임의 카운트다운 ETA를 보여주지 않는다.
runtimeBusy 앱 오류는 “코딩 도우미 작업이 끝난 뒤 다시 시도”로 안내한다.

## 5. 제출 UX

수동 제출 클릭 시 미저장 draft 수, 실행 중 작업 수, 마지막 확인된 저장 시각을 보여준다.
사용자가 제출 확정하면 서버가 sealing을 담당한다. 시간 만료는 확인창을 기다리지 않는다.
제출 실패는 작업 보존과 재시도 가능 여부를 보여주고 편집 화면을 몰래 다시 활성화하지 않는다.
제출 고정 후 파일/로그를 읽기 전용으로 탐색한다.
고정 시각이 마감보다 늦거나 마감 후 변화가 있으면 리포트까지 해당 조건을 유지한다.

## 6. 사후 질문·리포트

질문 입력은 서버에 임시 저장하고 answered/skipped를 명시적으로 확정한다.
시험 모드에서 coder tab은 읽기만 가능. API도 호출 차단.
리포트는 전체 점수보다 확인된 강점·보완점·근거를 먼저 보여준다.
근거 링크를 누르면 정확한 제출 파일/검증 실행/사용자 발언으로 이동한다.
미평가와 0점을 시각적으로 다르게 표현한다.
재평가 시 이전 결과와 version을 선택할 수 있으며 이전 결과를 숨기거나 덮어쓰지 않는다.

## 7. 개발 모드와 재생

개발 모드의 모든 화면에 지속 배지를 표시한다.
가상 응답은 “재생 데이터”, 라이브 응답은 “로컬 Codex”로 표시.
재생 기능은 동일한 제품 API·이벤트 계약을 사용한다. provider wire를 UI fixture로 직접 사용하지 않는다.
실패 입력: 인증 오류, 스트림 단절, 중복 이벤트, 저장 실패, file conflict, 검사 timeout, 잘못된 evidence ID, snapshot 실패.
비공개 기준 열기·시간 변경·모델 변경은 conditions에 기록한다.
개발자 화면의 원시 요청·출력은 가림 처리 후 보여준다.

## 8. 접근성과 검증

모든 버튼에 이름, 상태에 텍스트, 키보드 focus, 충분한 대비 제공.
role 색상만으로 상대를 구분하지 않는다.
긴 메시지·한글 IME·작은 창·대량 터미널 출력·서버 재시작을 확인한다.
UI-01 역할 입력 보존, UI-02 파일 충돌, UI-03 재연결 delta,
UI-04 단계 URL 접근, UI-05 만료 제출, UI-06 근거 링크,
UI-07 조건 배지, UI-08 키보드/IME를 완료 기준으로 사용한다.
