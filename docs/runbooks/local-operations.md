# 로컬 운영·복구

## 데이터 위치와 포트

기본 제어 주소는 `http://127.0.0.1:4310`이다. `PORT`로 포트를 바꿀 수 있다. `WPL_DATA_DIR`로 새 앱 소유 데이터 폴더를 지정할 수 있다. 기존 폴더를 지정하면 그 안의 DB·시도·고정 제출본을 복원한다. 다른 프로그램의 폴더를 데이터 폴더로 사용하지 않는다.

브라우저의 시작 토큰은 한 번만 쿠키로 교환된다. 시작 연결이 만료되면 페이지를 다시 연다. 서버 재시작 후 기존 쿠키는 무효하므로 새로고침한다. 동일 서버에서 여러 탭을 열어도 유효한 세션을 재사용한다. 서로 다른 제어 포트는 각각 다른 쿠키 이름을 사용해 인증을 덮어쓰지 않는다.

## 중단과 복구

정상 종료는 실행 중인 앱 프로세스와 터미널을 정리한다. 갑작스러운 중단 후 진행 중 모델 작업은 `uncertain`으로 남는다. 요청을 자동 재전송하지 않는다. 작업 상태·원래 대화를 조회하고, 실행이 중복될 가능성을 확인한 뒤 명시적으로 재시도한다.

코딩 대화는 동일 프로필이면 `thread/resume`으로 복원한다. 도구 목록이 바뀌거나 기존 대화를 복원할 수 없으면 새 대화를 만들고 공개된 대화·선택 공유·사용자 메모를 재구성한다. 담당자·평가자는 세션을 다시 만들어도 역할별 허용 맥락만 받는다.

서버가 소유한 자식 프로세스에는 nonce를 넣는다. 재시작 때 해당 PID의 nonce가 일치할 때만 종료한다. 소유권을 확인할 수 없는 프로세스는 임의로 종료하지 않고 `orphaned`로 표시하며 제출을 보류한다. 외부에서 시작한 실행은 사용자가 직접 정리한다.

제출 중 중단되면 `submission_failed`로 복원한다. 제출 재시도는 기존 cutoff와 submission ID를 유지한다. 이미 manifest가 commit되었다면 파일 해시를 다시 검증한 고정본을 복구하고, 복사 단계에서 파일이 계속 바뀌면 오류를 표시한다. 고정본이 외부에서 변경되면 검증·평가를 차단한다.

## 시간과 충돌

시험 연습은 일시정지를 허용하지 않는다. 자유 연습은 실행을 정리한 뒤 실제 일시정지 시각을 기록한다. 기한은 서버가 검사하며 브라우저가 닫혀도 제출을 시작한다. 파일 저장에는 이전 SHA-256이 필요하다. 충돌 화면의 최신 내용과 작성 초안을 비교한 뒤 선택·병합한다.

## 데이터베이스

예약 과제의 PostgreSQL 컨테이너는 `wpl-pg-<앱 데이터 폴더 hash>` 이름과 `wpl.owner` label로 구분한다. 비밀번호는 앱 소유 `services/postgres.json`에 권한 0600으로 저장하고 로그에서 가린다. 시도와 검증 복사본은 다른 데이터베이스를 사용한다. 이미 있는 사용자 데이터베이스는 수정하지 않는다.

장비 과제 준비가 실패하면 Docker를 실행한 뒤 준비를 재시도한다. 앱을 사용하지 않을 때 Docker UI에서 해당 앱 label의 컨테이너를 정지할 수 있다. 데이터 보존이 필요하면 컨테이너·앱 데이터 폴더를 임의 삭제하지 않는다.

## 내보내기와 삭제

ZIP에는 보고서·공개 제출 파일·가림 처리된 근거만 들어간다. `.env`, 의존성, 비공개 과제 폴더, 로그인 파일은 포함하지 않는다. 내보내기 전 등록된 비밀값과 키 패턴을 검사한다. 바이너리의 임의 개인정보까지 자동 식별하는 도구는 아니다.

완료·종료된 시도만 삭제할 수 있다. 이어 연습이 참조하는 원본은 후속 시도를 먼저 삭제해야 한다. 삭제는 관련 DB 레코드, 앱 소유 파일, 연결된 내보내기와 미참조 근거만 정리한다. 삭제할 기록이 필요하면 먼저 ZIP을 내보낸다.

## 실행 환경 문제

macOS에서 `posix_spawnp failed`가 발생하면 `pnpm install`의 postinstall이 node-pty spawn-helper 실행 권한을 복구했는지 확인한다. `node tools/postinstall.mjs`로 앱 의존성의 helper만 재설정할 수 있다.

Codex 버전·실제 실행 경로·모델이 바뀌면 실제 연결 검사를 다시 실행한다. 제한된 역할에서는 호스트 환경이 없는 요청을 사용하고, 코딩에는 실제 바이너리의 정규 경로를 사용한다. 새 CLI 버전에서 이 조합을 지원하지 않으면 라이브 준비를 통과시키지 않는다.

## 편집 복구와 재시도

파일 초안은 시도·파일 경로별로 브라우저에 보관한다. 서버의 확정 응답 전에는 저장됨으로 표시하지 않는다. 저장 실패 후 새로고침하면 초안을 복구하되 자동 재전송하지 않으며 저장 버튼으로 재시도한다. 디스크 변경은 깨끗한 편집기에 반영하고, 미저장 초안이 있으면 비교 화면에서 선택·병합하도록 멈춘다.

같은 실패 작업의 재시도를 여러 번 눌러도 이미 접수된 재시도를 돌려준다. 서버 재시작으로 상태가 불명확한 부분 답변은 원문과 uncertain 표시를 함께 보존하고, 실행 전 대기 요청은 중단됨으로 남긴다.

일반 실행은 `pnpm build` 후 `pnpm start`를 사용한다. 개발용 `pnpm dev`는 과제·자료·검증 폴더 변경 때문에 작업 화면을 새로고침하지 않는다.

## 로그인 앱 미리보기

제어 화면과 과제 앱은 서로 다른 호스트로 분리한다. 브라우저가 삽입 화면의 로그인 쿠키를 제한할 수 있으므로 로그인 앱은 미리보기의 새 탭에서 테스트로 연다. 이 링크는 서버가 등록한 로컬 포트만 사용하며 새 탭의 opener를 제거한다. 쿠키 정책을 약화하거나 제어 세션을 과제 앱에 전달하지 않는다.

## 답변 표시와 터미널 화면 복구

- 담당자·코딩 도우미 답변 상태는 이벤트와 별개로 3초마다 다시 조회합니다. 탭으로 돌아오거나 **답변 상태 새로 확인**을 눌러도 같은 요청의 결과를 읽습니다. 새로운 모델 요청을 만들지 않습니다.
- 터미널은 출력과 행·열 크기를 순서대로 저장하고 재생합니다. **출력 복원 완료**는 재생 처리가 끝난 뒤 표시합니다. 재생 중 과거 터미널 질의에 대한 응답을 실행 중인 프로그램에 다시 보내지 않습니다.
- 출력이 흐트러지면 **화면 복원**으로 프로그램을 유지한 채 다시 그립니다. 이전 서버에 연결된 화면도 복원 후 다시 그리기를 지원하지만, 크기를 포함한 출력 기록은 서버 업데이트 후 새로 기록되는 출력부터 적용됩니다.
- 자유 터미널에 여러 창이 연결되면 같은 프로세스의 행·열 크기를 공유합니다. 현재 화면 크기에 맞추려면 터미널을 클릭합니다.
