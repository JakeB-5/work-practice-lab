# Work Practice Lab

**AI와 함께 요구사항을 파악하고, 제한 시간 안에 구현·검증·제출까지 연습하는 해커톤 연습용 로컬 웹 앱입니다.**

해커톤에 나가기 전 혼자 실전 흐름을 연습하거나, AI에게 일을 맡기는 방법과 자신의 판단을 돌아보는 데 사용합니다. 한국어 과제, 업무 담당자 AI, 코딩 도우미, 작업 공간, 사후 질문과 평가 리포트를 제공합니다.

Cofa의 공개된 업무 수행·평가 흐름에서 영감을 받은 독립적인 연습 프로젝트입니다. Cofa 또는 OpenAI의 공식 제품·제휴 서비스가 아니며, 실제 시험 문제·내부 채점 알고리즘·공식 점수를 재현하지 않습니다. **점수는 해커톤 연습과 피드백을 위한 자체 평가입니다.**

## 어떤 연습을 하나요?

```text
과제·모델 선택 → 담당자에게 질문 → AI와 구현 → 실행·검증
    → 제출본 고정 → 사후 질문 5개 → 점수·근거·개선점 확인
```

- **담당자 대화:** 업무의 문제, 우선순위와 예외 조건을 질문하며 요구사항을 발견합니다.
- **코딩 도우미:** 필요한 담당자 답변을 직접 골라 공유하고 구현을 요청합니다.
- **작업 공간:** 파일 편집기, 터미널, 앱 미리보기, 자동저장과 충돌 해결을 제공합니다.
- **시간 관리:** 자유 연습, 시험 연습, 개발 모드를 선택합니다. 시험 연습은 시간을 멈출 수 없습니다.
- **제출·회고:** 제출 시점의 파일과 작업 기록을 고정하고, 본인의 판단과 이해를 사후 질문으로 설명합니다.
- **평가:** 기술·의도·인지 각 100점, 총 300점과 항목별 근거를 확인합니다. 리포트·제출본을 ZIP으로 내보낼 수 있습니다.
- **모델 제한:** 과제마다 허용할 모델을 복수 지정하고 응시 시 그중 하나를 선택합니다.

| 기본 과제 | 연습 내용 | 기본 시간 |
| --- | --- | --- |
| 고객 응대 연습 도구 | 사용자 필요 파악, AI 피드백, 작은 서비스 완성 | 120분 |
| 촬영 장비 대여 예약 | 예약 규칙, 권한, 중복 방지, 데이터 일관성 | 150분 |

상품·사용자·업무 상황은 가상입니다. 처음에는 고객 응대 과제로 시작하면 좋습니다.

## 설치 전 준비

| 준비물 | 설명 |
| --- | --- |
| Node.js 24 이상 | 내장 SQLite를 사용합니다. [Node.js](https://nodejs.org/)에서 설치하세요. |
| pnpm 12.9.1 | 저장소에 지정된 패키지 관리자 버전입니다. |
| Git | 저장소를 내려받는 데 사용합니다. |
| Codex CLI와 로그인 | 실제 AI 모드에 필요합니다. 사용 가능한 모델은 계정에 따라 다릅니다. |
| Docker | **장비 예약 과제**에 필요합니다. 앱이 PostgreSQL 16 컨테이너를 준비합니다. |
| Chromium | 아래 Playwright 설치 명령으로 준비합니다. 앱 검증에 사용합니다. |

현재 검증 환경은 **macOS Apple Silicon, Node.js 24.14.0, Codex CLI 0.163.0**입니다. Linux·Windows의 전체 흐름은 검증하지 않았습니다. App Server의 실험적 권한 기능을 사용하므로 CLI 버전이 달라지면 앱에서 연결·권한 검사를 반드시 실행하세요.

### 1. pnpm과 Codex 준비

Node.js와 Git이 설치된 터미널에서 실행합니다. 아래는 이 프로젝트에서 검증한 버전을 설치하는 예시입니다. 이미 설치돼 있다면 버전과 로그인 상태를 확인하세요.

```sh
npm install -g pnpm@12.9.1
npm install -g @openai/codex@0.163.0
codex login
codex login status
```

Codex 설치·로그인은 [공식 CLI 안내](https://learn.chatgpt.com/docs/codex/cli)와 [공식 인증 안내](https://learn.chatgpt.com/docs/auth)를 참고하세요. 이 앱은 로컬 Codex 로그인을 사용하며 앱에 API 키를 별도로 입력하지 않습니다. 실제 AI 요청은 해당 계정의 이용량을 사용합니다.

### 2. 프로젝트 설치

```sh
git clone https://github.com/JakeB-5/work-practice-lab.git
cd work-practice-lab
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm build
pnpm start
```

브라우저에서 **[http://127.0.0.1:4310](http://127.0.0.1:4310)** 을 엽니다. 실행한 터미널을 열어 두세요. 종료는 `Ctrl+C`입니다.

### 3. 처음 실행할 때

1. 우측 상단 **연결 설정**을 엽니다.
2. Codex 실행 파일과 모델을 확인하고 설정을 저장합니다. 실행 파일을 찾지 못하면 `which codex`로 확인한 경로를 입력하세요.
3. **실제 연결·권한 검사**를 실행합니다. 실제 응답, 작업 폴더 접근, 권한 제한, 중단과 복원을 확인하므로 모델 이용량을 사용합니다.
4. 과제를 고르고 **로컬 Codex · 실제 AI**와 사용할 모델을 선택합니다.
5. **작업 공간 만들기 → 환경 준비 → 연습 시작** 순서로 진행합니다.

장비 예약 과제는 환경 준비 전에 Docker를 실행하세요. PostgreSQL을 직접 설치하거나 비밀번호를 입력할 필요는 없습니다.

화면 흐름만 먼저 살펴보려면 **재생 데이터**를 선택할 수 있습니다. 재생 모드는 실제 AI 구현·채점을 하지 않으며, 표시된 0점은 화면 검증용 예시입니다. 장비 예약 과제의 환경 준비에는 재생 모드에서도 Docker가 필요합니다.

## 과제마다 허용 모델 정하기

1. 과제 상세에서 **과제 새 버전 제작**을 엽니다.
2. **사용 가능한 AI 모델**의 `모델 제한 없음`을 해제합니다.
3. 허용할 모델을 하나 이상 선택하고 **새 버전 저장**을 누릅니다.

응시 화면에는 허용 목록과 현재 Codex 모델 목록에 모두 있는 모델만 나타납니다. 선택한 모델은 응시 기록에 고정되며 담당자·코딩 도우미·평가·과제 앱 AI에 사용됩니다. 서버도 허용하지 않은 모델 요청을 거부합니다. 기존 과제 버전과 응시 기록은 그대로 유지됩니다.

예를 들어 계정에 표시되는 Sol·Terra·Luna 계열 모델 중 특정 버전만 허용할 수 있습니다. 모델 이름이나 버전을 임의로 추가하지 않으며, 실제 사용 가능 여부는 연결된 계정의 목록과 실행 결과에 따릅니다. 실패하면 오류를 표시하고 다른 모델로 자동 대체하지 않습니다.

## 평가 결과 읽기

각 축에는 4개 항목이 있고, 항목별로 0~4점을 판정해 축별 100점으로 환산합니다.

| 축 | 살펴보는 내용 |
| --- | --- |
| 기술 | 실제 동작, 업무 규칙, 검증, 실패 처리 |
| 의도 | 문제·제약 파악, 우선순위, AI에게 전달한 맥락, 결과에 따른 판단 |
| 인지 | 선택 이유, 동작 원리 이해, 한계 인식, 대안 비교 |

최종 결과는 12개 항목과 총점이 모두 확정돼야 완료됩니다. 질문·검증 기회 이후 역량을 입증하지 못하면 이유를 명시해 0점으로 반영합니다. 기록 누락이나 실행 환경 오류는 응시자의 0점으로 바꾸지 않고 복구·재시도 대상으로 남깁니다. 재평가는 이전 결과를 보존하며 새 버전으로 생성합니다.

모델 판단은 같은 근거에서도 달라질 수 있습니다. 공인 성적이나 채용 적합성을 보증하지 않습니다. 공개 저장소에 과제와 자체 채점 기준이 포함되므로, 처음 보는 문제처럼 연습하려면 `scenarios/*/private`를 미리 읽지 마세요. 여기서 `private`는 앱의 응시 화면·작업 폴더에 전달하지 않는다는 뜻이며, 공개 저장소의 접근 제한을 뜻하지 않습니다.

## 개발·검사

```sh
pnpm dev           # 개발 서버
pnpm check         # TypeScript 검사
pnpm test          # 단위·통합 검사
pnpm build         # 배포용 화면 빌드와 타입 검사
```

추가 검사:

- `pnpm test:e2e`: 별도 설치된 Ego Browser에서 실제 화면 흐름을 검사합니다. 일반 앱 사용에는 Ego Browser가 필요하지 않습니다.
- `pnpm test:live`: 로그인된 Codex와 Docker로 두 과제의 실제 실행을 검사합니다. 모델 이용량과 실행 시간이 필요합니다.
- `pnpm exec tsx tools/runtime-probe/model-policy.ts`: 실제 모델 선택·세션 적용을 확인합니다.

공개 준비 시 단위·통합 검사 **53개**와 빌드를 확인했습니다. 앞선 개발 과정에서 두 과제의 실제 AI 수행·채점, 모델 제한 설정과 화면 흐름을 확인했습니다. 공개 소스는 모든 계정·운영체제의 동작을 보증하지 않습니다. [검증 범위](docs/evidence/README.md)를 참고하세요.

## 데이터와 실행 범위

- 기본 데이터 폴더는 `.wpl-data/`입니다. 응시 파일, 대화, 제출본, SQLite, 앱용 DB 설정이 저장됩니다.
- `.wpl-data/`, 환경변수 파일, 로그, 내보낸 리포트와 로컬 검증 산출물은 Git에 올리지 않습니다.
- 앱은 `127.0.0.1`에 바인딩되는 개인용 로컬 실행 환경입니다. 공개 인터넷이나 다중 사용자 시험 서버로 배포하는 기능은 포함하지 않습니다.
- 과제 앱 미리보기는 별도 로컬 주소에서 열립니다. 로그인 앱은 **새 탭에서 테스트**를 사용하세요.
- 포트를 바꾸려면 `PORT=4312 pnpm start`, 데이터 위치를 바꾸려면 `WPL_DATA_DIR=/원하는/경로 pnpm start`로 실행할 수 있습니다.
- 모델에 전달된 과제·대화·코드는 해당 AI 서비스의 처리 대상입니다. 연습에는 가상 자료를 사용하세요.

## 자주 막히는 부분

| 증상 | 확인할 것 |
| --- | --- |
| Codex 실행 파일을 찾지 못함 | `which codex`와 앱 연결 설정의 실행 경로 |
| 모델이 없거나 요청 실패 | `codex login status`, 계정 모델 목록, 과제 허용 목록 |
| 연결·권한 검사 실패 | Codex 버전과 오류 내용. 검사 실패를 무시하고 실제 실행을 시작하지 않습니다. |
| 장비 예약 환경 준비 실패 | Docker 실행 상태를 확인한 뒤 환경 준비 재시도 |
| macOS 터미널 `posix_spawnp failed` | `node tools/postinstall.mjs` 실행 후 앱 재시작 |
| `node-pty` 설치·컴파일 실패 | macOS의 Xcode Command Line Tools 등 로컬 빌드 도구 확인 |
| 수정한 화면이 그대로임 | `pnpm build` 후 재시작하거나 `pnpm dev` 사용 |
| 평가 실패 | 화면 오류를 확인하고 검사·답변을 보완한 뒤 재시도. 기존 제출본·성적은 보존됩니다. |
